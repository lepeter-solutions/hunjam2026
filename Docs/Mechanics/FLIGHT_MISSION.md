# Flight mission: collisions and screen fade

## Purpose and sources
Manhattan starts fully black and reveals the cockpit over `FlightVehicle.fadeDuration` (10 seconds by default). Player impact with the enemy aircraft wins; player impact with other external colliders loses. The enemy reaching a collider beneath the `Twins` hierarchy loses. Sources: `Scripts/Player/FlightVehicle.cs`, `Scripts/Characters/TerroristAi.cs`, the existing Image/Canvas and aircraft in `Scenes/Manhattan.unity`.

## State and integration
- Startup creates `FullViewFade` with alpha exactly 1 in Awake. Its URP shader writes full-screen clip coordinates with stereo instancing support, ZTest Always and overlay render queue; coverage does not depend on Canvas size, FOV or eye separation. The old Image renderer is disabled. The overlay follows `DemoPlayer.View` through the Meta camera handoff. XR startup waits for tracking readiness, holds opaque black for 0.5 seconds, then fades using unscaled time. `Scripts/Player/FullViewFade.cs` and `Assets/Resources/FullViewFade.shader` implement this; Resources keeps the shader available in builds. Game-over restores overlay alpha 1 and cancels reveal.
- Player mission collisions use `collisionGameOverEnabled` and a linked `terroristAi`, independently of the optional training `automaticResetEnabled`/`resetOnCollision` controls. Without a mission link the original gated, speed-threshold training reset remains. Aircraft identification searches parent components, so child colliders work.
- Game-over is latched once on TerroristAi. It cancels the player's startup fade, sets the screen black, freezes both aircraft while leaving head tracking active, stops music/engine audio and optionally plays the death clip. Missing audio references do not interrupt scene transition. The startup fade cannot overwrite the black ending.
- After `restartDelay` (unscaled seconds), loss reloads the active scene by its **name**, not Scene.ToString(). Win loads `winSceneName` if configured and available; otherwise it stays black and logs a clear warning. The original implementation only logged an epilogue message; no epilogue scene is selected automatically.

## Collision geometry
Static inspection found 39 scene MeshColliders with `m_Mesh: {fileID: 0}`, including the enemy. Such a collider has no collision geometry. TerroristAi initialization handles the current scene's enabled, non-trigger, empty **static** MeshColliders: it assigns child MeshFilter meshes to colliders on those mesh objects, preserving their transforms and existing valid shapes. Empty roots with resolved child shapes are disabled. Roots without suitable geometry warn. Dynamic/kinematic hierarchies and intentional triggers are excluded from building setup.

The enemy uses a dynamic Rigidbody with gravity off, frozen rotation, interpolation and Continuous Dynamic detection. FixedUpdate sets forward velocity instead of teleporting its Transform. Invalid/concave enemy mesh colliders are disabled; when no valid solid body collider exists, a BoxCollider is fitted to child mesh bounds. This is an approximate full-aircraft hitbox, not per-wing collision. Existing valid primitive/convex colliders take precedence. The player's existing aircraft collider is retained, with Continuous Dynamic detection enabled.

## Tuning and extension
Set the same fade Image on FlightVehicle and TerroristAi; keep the mission link on FlightVehicle. `fadeDuration` controls reveal speed; `restartDelay`, `deathAudioClip`, music/player AudioSources and `winSceneName` control the ending. Enemy `speed` is metres/second. The existing `Twins` ancestor name remains the target convention. For precise collision replace the enemy fallback with authored primitive/convex compound shapes. Building collision setup is runtime only and can be replaced with authored colliders on the actual mesh children.
